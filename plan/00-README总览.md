# 00 - README 总览：收藏夹体检工具（bookmark-doctor·中文站点友好）

**仓库**：`10-16-bookmark-doctor`
**性质**：不参赛项目题，发布 GitHub **公开**仓库，署名 yuluo554
**版本**：v2（2026-10-15，M0 骨架完成时更新；v1 为题定稿版）

一句话定位：导入浏览器导出的 `bookmarks.html`，一次跑完失效检测 + 重复合并 + 长期未访问画像 + 一键导回，**并专门适配中文站点**——微信文章 / 知乎 / B站 / 微博的链接不能按普通 HTTP 状态一刀切。零依赖、纯本地 CLI（不是浏览器扩展）。

**当前状态**：🚧 开发中 —— M0（计划先行与骨架）、M1（数据先行）、M2（解析）、M3（检测与去重）、M4（基准）、M5（交付）已完成；下一棒 M6（发布）。

## 2. 决策记录

### 2.1 题定稿期决策（v1，2026-10-15）

| # | 决策 | 备选方案 | 结论与弃选理由 |
|---|---|---|---|
| D1 | **形态 = 本地 CLI + 本地 HTML 报告**（零依赖、无服务器、无登录、无 GPU） | ①做 Chrome 扩展；②做自托管 Web 服务 | **弃"做 Chrome 扩展"**：主对手 Alanrk/LazyCat-Bookmark-Cleaner 1853★ 已占据扩展形态，且企业浏览器策略下扩展不可装、国产浏览器生态碎片化扩展适配成本高；**弃"自托管 Web 服务"**：linkwarden 20114★ / shiori 11668★ / linkding 11304★ 已占据自托管形态，且与"浏览记录不愿上云"的隐私诉求相悖。本地 CLI 是这两者之间的空白形态 |
| D2 | **核心亮点 = 中文站点反爬降级规则库** | 做通用 URL 死链检查 | **弃"通用 URL 检查"**：lycheeverse/lychee 4007★ 已占据 URL 级检查，正面竞争无胜算；且通用检查器对中文站点（403/302/521）大量误报，恰是差异化价值所在 |
| D3 | **首期不做"收藏内容存档"** | 做页面内容归档 / 全文检索 | **弃"收藏内容归档"**：合规风险高（内容抓取）+ 巨头林立（archive 类项目成熟），且与"只探测链接状态"的合规红线冲突。全文检索降级为扩展项（导航站 FTS5） |
| D4 | **判定语义区分"失效"与"待复核"** | 二态（失效 / 存活） | 二态会把"网络不可达"和"403/521 反爬拦截"误判为失效，是本题最核心的误报来源。改为三态（失效 / 待复核 / 存活），反爬与不可达一律落"待复核" |
| D5 | **纯本地零上传，探测只做单次** | 接云端 API 做批量检测 / 接 LLM 辅助判定 | 书签是个人浏览记录，隐私红线要求零上传；批量检测有被判恶意扫描的合规风险。单次探测 + 降频是合规底线 |
| D6 | **去重以 URL 规范化为主，标题相似仅作辅助** | 仅按标题相似度去重 | 标题相似会误删不同文章的同名链接（如多篇"年度总结"）；URL 规范化（剥追踪参数、短链映射）可复现且可审计，标题相似只提示不自动删 |
| D7 | **不预设硬数字**（书签数 / 基准用例数 / 命中率） | 题面写死测试规模 | 数字随实现漂移，写死必然失真。只写指标口径与覆盖度要求（各易错形态最低覆盖项进基准 manifest） |

### 2.2 骨架期决策（v2，2026-10-15，M0）

| # | 决策 | 备选方案 | 结论与理由 |
|---|---|---|---|
| D8 | **Python ≥ 3.8，stdlib-only 运行时** | 3.9+/3.10+ 底线；引入运行时依赖 | 本机默认通道即 3.8.8，底线 3.8 可双通道实测（3.8 系统通道 + 3.12 venv 通道）；"零依赖"是 README 的第一卖点，运行时依赖会稀释定位。3.8 兼容写法成本可控（禁 3.9+ 语法糖、`Path.write_text(newline=)` 禁用等，进 K 清单） |
| D9 | **CI 三矩阵 = windows×{3.8,3.12} + ubuntu×3.12** | 四矩阵（ubuntu 也守 3.8） | ubuntu 新镜像对 3.8 支持存疑（skill 实录），旧解释器只在 windows 守；首推实测后按实况补记，不硬凑 |
| D10 | **LLM 全程不使用** | 探测失败时用 LLM 兜底判定 | 全链路确定性（题面 1.3 方法论文脉）：结论 100% 可复现、零 API 依赖、基准可离线复跑、无上传面（D5 联动）。显式记录以免误读为遗漏 |
| D11 | **构建/元数据 = PEP 621 pyproject + setuptools** | poetry / hatch / setup.py | 构建面最小化；3.8 兼容 |
| D12 | **LICENSE = MIT** | Apache-2.0 / GPL | 工具类小项目最常见、无专利条款负担；对外发布动作前经用户确认（待定决策表 A3） |
| D13 | **package-dir = src 布局** | 平铺布局 | src 布局强制"测试跑的是安装态"，与"测试面 = 安装面 = README 指令面"纪律配套；顶层 `benchmark/` 未进安装面的历史教训（skill 实录）从布局上规避 |
| D14 | **UIR 字段名与 CLI 规格为"冻结草案"** | 直接定稿 | 骨架期无实测数据支撑的字段细节（如 Chrome 纪元换算边界）留到 M2 实测后冻结为 K 清单——避免"计划猜、实现改"的两处真相 |
| D15 | **探测首期串行** | 并发探测 + 并发降频控制 | 串行使降频与确定性最简单（输出顺序稳定）；并发为缓议扩展项 |
| D16 | **dev extras 含 pytest + pyyaml** | 仅 pytest | pyyaml 支撑 CI workflow 解析守门（防"非法 YAML → 不建任何 job"的静默失败，skill 实录过的缺陷族）；测试面 = 安装面纪律要求测试真 import 的库全部进 README 安装通路 |
