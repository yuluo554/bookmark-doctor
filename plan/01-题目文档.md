# 题目文档：收藏夹体检工具（bookmark-doctor·中文站点友好）

> **项目性质**：不参赛项目题（发布 GitHub **公开**仓库，署名 yuluo554）
> **目标产出**：`10-16-bookmark-doctor`（收藏夹体检工具·中文站点友好）
> **版本史**：v1（2026-10-15 定稿）
>
> **定位宣言**：导入浏览器导出的 `bookmarks.html`，一次跑完失效检测 + 重复合并 + 长期未访问画像 + 一键导回，**并专门适配中文站点**——微信文章 / 知乎 / B站 / 微博的链接不能按普通 HTTP 状态一刀切，通用检查器在这里大量误报。零依赖、纯本地 CLI（不是浏览器扩展）。

---

## 1. 介绍

### 1.1 痛点

浏览器收藏夹是绝大多数人用了十年以上的"个人知识库"，但它几乎从不被维护：

- **失效检测一刀切，中文站点被误杀**：通用链接检查器只看 HTTP 状态码，判定"非 200 = 失效"。但中文内容平台普遍部署反爬风控——知乎对非浏览器请求返回 **403**、微博返回 **302** 需跟随跳转、B站返回 **301/302**、掘金/CSDN 等常被 CDN 反爬拦截返回 **521**。这些站点的链接**在浏览器里点开完全正常**，在通用检查器里却全部变成"死链"。一刀切的后果是：用户看到几十条误报，直接不再信任这份报告。
- **收藏夹只增不减，重复越滚越多**：同一篇文章从微博、知乎、公众号三个入口被收藏三次，URL 形态各不相同（带 `utm_*` 追踪参数、带 `?share_token=`、短链 vs 长链、http vs https），肉眼无法合并。
- **"存了就等于看过"的错觉**：大量链接从收藏之日起再未访问，但没有任何工具告诉用户"你这 800 条里有 300 条两年没打开过"。
- **导不回浏览器，闭环断在最后一步**：清理结果只能看，不能一键导回成浏览器可导入的格式，用户要手工重建收藏夹。

### 1.2 形态与开源空白

- **形态错位**：GitHub 检索式 `bookmark manager`（基准日 **2026-10-15**，`gh api search/repositories`）返回 **7891** 个结果，但头部全部是**自托管服务器**形态——linkwarden **20114★**、shiori **11668★**、linkding **11304★**。它们要求用户自建服务端（Docker/数据库/常驻进程），与"企业浏览器受限、不想搭服务、只想要一个本地 CLI"的用户需求错位。
- **中文细分对手**：
  - Alanrk/LazyCat-Bookmark-Cleaner **1853★**（**Chrome 扩展**，JS，2026-10-13 活跃）——**主对手**，但形态是扩展，装不了扩展的环境（企业浏览器策略、部分国产浏览器）不可用。
  - ricocc/rico-bookmark-manager **139★**（2026-06，Skill + 无依赖 Python CLI，做分类/去重/查死链/导回）——**最接近**的形态，但未针对中文站点反爬做降级规则，死链判定仍按 HTTP 状态一刀切。
  - waangzh/re-bookmarks **23★**——**依赖 OpenAI API**，违背"纯本地零上传"。
  - bennyji/BookmarkDeduplicator **3★**、FairlyHe/he-fox-bookmark **0★**、Topkill/chrome-bookmarks-cleanup **0★**——全为 Chrome 扩展，低星。
- **检索式空白**：`跨浏览器 书签 合并 去重` → **0** 结果；`浏览器 书签 导航站 本地` → **0** 结果；`书签 失效检测` → **2**（均 0★）；`cross browser bookmark sync` → **31**，头部 BrowSync **107★**（**macOS only**）。
- **通用链接检查器不覆盖本场景**：lycheeverse/lychee **4007★**——URL 级检查器，不解析书签树、不管中文站点反爬降级。
- **空白点**：**本地 CLI / 单文件**（扩展装不了、企业浏览器受限）+ **中文站点专门降级策略** + **"长期未访问画像 + 一键导回"闭环**三者同时成立的成体系开源项目未见（⬜ 软论据，依检索式与基准日记录于 `data/README.md`）。
- **中国用户特有约束**：国内浏览器生态碎片化（Chrome / Edge / 360 / QQ / 夸克），书签格式各异；且用户**不愿把浏览记录同步到境外云**。

### 1.3 方法论文脉

本题遵循"**规则库 + 合成数据植入真值 + 内置基准 + 离线交付**（纯本地 CLI + 本地 HTML 报告，零上传）"的方法论文脉：把"中文站点链接不能按 HTTP 状态一刀切"沉淀为**可核验、可版本化的降级规则库**，而不是把判定交给 LLM 聊天。

### 1.4 AI 时代独特性拷问

"检查 + 报告"类通用功能不算独特。本题的独特性锚在三处：**①持久状态**（书签快照 + 访问画像需要历史，LLM 单轮聊天给不了）；**②进入既有工作流的交付物**（一键导回浏览器可导入格式，闭环落回用户的真实工具链）；**③可复现测量基建**（内置合成书签集 + 植入真值基准，任何人可一键复跑，判定不漂移）。

## 2. 任务要求

首期限定 **5 个模块**，逐个交付。每个模块遵守统一确定性纪律：**任何降级规则、判定依据、阈值，未挂实测记录核对不得落库、不得生效、不得进入判定路径。**

### 模块 ①：多浏览器书签导入与跨浏览器合并

- **输入**：浏览器导出的书签文件——Netscape Bookmark HTML 格式（Chrome / Edge / Firefox 导出通用）与 Chrome / Edge 的 `Bookmarks` JSON。
- **输出**：统一中间表示的书签树（文件夹层级 + 标题 + URL + 添加时间 + 来源浏览器标识），多份输入可合并为一棵树。
- **确定性纪律**：同一文件 → 同一中间表示，无随机性、无 LLM；解析不到的字段（如缺失添加时间）如实落 `未知`，不得猜测补全；解析失败的文件必须显式报错退出，不得静默吞掉。
- **扩展项**：360 / QQ / 夸克浏览器私有格式适配。

### 模块 ②：中文站点感知的失效检测（核心亮点）

- **输入**：模块①的书签 URL 列表。
- **输出**：逐条链接的状态分类结果 + 判定依据。
- **HTTP 状态分类**：网络不可达 / 超时 / 重定向（跟随跳转后终态）/ 2xx 存活 / 4xx / 5xx，**明确区分"网络不可达 ≠ 失效"**（DNS 失败、连接超时属"待复核"而非"失效"）。
- **平台反爬降级规则库**：把实测的中文站点响应特征编码为**版本化规则库**——
  - **403**（如知乎非浏览器请求）→ 判"可能存活，需人工复核"，**不判失效**；
  - **302**（如微博）→ 跟随跳转后按终态判定，仍为风控则判"待复核"；
  - **301/302**（如 B站）→ 按降级判定，不直接判失效；
  - **521**（反爬 CDN 拦截，如掘金/CSDN 真链接常返回）→ 判"CDN 拦截，需人工复核"，**不判失效**。
- **确定性纪律**：降级规则库每条规则必须携带**实测记录锚点**（站点 + 观测状态 + 观测日期 + 查证状态 ✅/⬜），缺锚点的规则不得被引擎加载生效；阈值（超时秒数、重试次数、降频间隔）**一处定义、多处引用**（见 `data/README.md` 数值口径纪律）。
- **合规纪律**：只对用户自有书签做**单次探测**，不批量爬取、不登录、遵守降频。
- **扩展项**：定时体检（本地计划任务触发，非服务端常驻）。

### 模块 ③：重复合并（URL 规范化去重 + 标题相似）

- **输入**：模块①的书签树。
- **输出**：重复组清单 + 建议保留项 + 合并动作。
- **去重规则**：URL 规范化（大小写域名归一、剥离 `utm_*` / `share_token` 等追踪参数、http/https 归一、去尾斜杠、短链与长链的已知映射）+ 标题相似度辅助判定。
- **确定性纪律**：规范化规则**一处定义**（规范化函数 + 规则表），去重结果可复现；标题相似只作**辅助提示**，不得仅凭相似度自动删除，删除动作必须由用户确认或按显式策略执行。
- **边界纪律**：短链与长链映射只收录**已实测可解析**的映射，未实测的不猜。

### 模块 ④：长期未访问画像与报告（本地 HTML + 一键导回）

- **输入**：模块①-③的结果 + 书签的添加时间。
- **输出**：**本地 HTML 报告**——失效清单 / 待复核清单 / 重复清单 / 长期未访问画像 / 建议清理清单；并提供**一键导回**：导出为浏览器可导入的 Netscape Bookmark HTML 格式。
- **确定性纪律**：报告中不得出现生成逻辑自行编造的链接状态；所有状态必须来自模块②/③的判定结果；"长期未访问"的判定口径（基于添加时间的分档）一处定义。
- **隐私纪律**：报告与导出文件**纯本地生成、零上传**，不写入任何远端。

### 模块 ⑤：真值基准（合成书签集 + 植入真值）

- **输入**：合成书签集生成配置（假域名白名单，见 `data/README.md` 合成数据纪律）。
- **输出**：**合成书签集**（Netscape HTML + Chrome JSON 双格式）+ **植入真值**（哪些应判失效 / 哪些是重复 / 哪些 403/521 应标"待复核"而非失效）。
- **确定性纪律**：每个合成书签集的"植入真值"必须在元数据中**显式登记**，与检测引擎输出自动比对；基准随项目发布，任何人可一键复跑。
- **覆盖度口径**：合成集必须显式覆盖三类易错形态——①"403/521 被误判失效"（应判待复核）；②"网络不可达被误判失效"（应判待复核）；③"重复但 URL 形态不同"（应合并）。各形态最低覆盖项写进基准 manifest，不写会漂移的硬数字。

### 扩展项（非首期门槛）

- 360 / QQ / 夸克浏览器私有书签格式适配。
- 导航站静态 HTML 生成（+ 本地 SQLite FTS5 全文检索，中文分词用 wangfenjin/simple 870★）。
- 定时体检（本地计划任务）。

## 6. 边界与非目标

### 6.1 合规红线

- **不做批量爬取**：只对用户自有书签做**单次探测**（每个 URL 一次），不遍历站点、不抓取站内其他页面。
- **不登录**：不携带任何账号凭据，不模拟登录态。
- **不做内容抓取**：**只探测链接状态**（HTTP 状态/重定向终态），不抓取、不存档页面内容。
- **遵守降频**：探测遵守降频间隔，避免被目标站点判定为恶意扫描。

### 6.2 隐私红线

- **书签是个人浏览记录**：纯本地处理，**零上传**——书签内容、判定结果、报告、导出文件全部不出机。
- **探测请求不携带任何用户标识**：不发送 cookies、不发送登录态、不做用户指纹。

### 6.3 非目标

- **不做云同步**：不做跨设备同步、不做服务端常驻（明确区别于 linkwarden/shiori/linkding 的自托管形态）。
- **不做"收藏内容存档"**：页面内容归档属另一个方向（合规风险 + 巨头林立），本项目只做链接状态与收藏夹结构治理。
- **不做浏览器扩展**：首期形态固定为本地 CLI + 本地 HTML 报告（扩展形态已由主对手 1853★ 占据，且企业浏览器策略下扩展不可装）。

### 6.4 结论纪律

- 判定结果区分"失效"与"待复核"：**网络不可达、403/521 反爬拦截一律不得直接判失效**，必须落"待复核"，由用户人工确认。
- 报告必须携带免责说明：判定为**辅助参考**，链接是否真的失效以用户浏览器实际打开为准。
- 题面不写会漂移的硬数字（测试书签数、基准用例数、命中率具体值），只写指标口径与门槛来源；数值口径一处定义、多处引用。

### 6.5 品牌隔离

本项目不提及任何姊妹项目，独立署名与独立定位陈述。
