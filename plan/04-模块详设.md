> 状态：已定稿（2026-10-15，sprint 阶段 0）。本文档给"每个模块怎么建"；判定语义总口径见 `plan/02` §5，架构分层见 `plan/03`。
> 标注 **[冻结草案]** 的表格/接口在对应里程碑实现时冻结为"既定口径 K 清单"条目，冻结后属"动了会打挂测试"的约定。

## 模块① 多浏览器书签导入与跨模块合并（M2）

### 1.1 输入 / 输出
- 输入：Netscape Bookmark HTML（`.html`/`.htm`）、Chrome/Edge `Bookmarks` JSON（`.json`）；可多份。
- 输出：`tree.json`（UIR，见 plan/03 §2）+ 合并摘要（来源数、条目数、未知字段计数）。

### 1.2 解析器要点
- Netscape HTML：`html.parser` 子类按 `<DT><H3>`（文件夹）/ `<DT><A HREF ADD_DATE>`（书签）流式解析；`<DL>` 嵌套 = 层级；HTML 实体解码；`ADD_DATE` 为 epoch 秒字符串，缺失/非法 → `null`。
- Chrome JSON：`roots` 树递归（`bookmark_bar` / `other` / `synced`），节点 `type` 区分 folder/url，`date_added`（Chrome 纪元 = 1601 起的微秒）**显式换算**为 epoch 秒；格式缺失字段 → `null`。
- 解析失败（坏 HTML 结构 / 坏 JSON / 空文件 / 读写失败）→ 显式报错（文件级错误码 + 人读消息）→ 退出码 2，**不落盘半成品**。

### 1.3 合并规则 [冻结草案]
- 同 URL（原文精确匹配）多来源 → 合并为一条，`source` 记录全部来源，`add_date` 取**最早非空值**（可追溯）；
- 文件夹层级**不拍平**：按来源各自保留树形路径；跨来源"同名文件夹"的合并策略 = 保留来源树 + 合并视图中按 URL 去重（不做目录级自动合并，避免误判）；
- 输出条目顺序：按 `(来源顺序, 文件内序号)` 稳定排序；`id = sha1(source|seq)` 前 12 位（确定性）。

### 1.4 验收判据
- 双格式合成集**往返一致**（解析 → 再导出 → 再解析，字段级相等）；
- 缺字段样例落 `null` 且报告显式计数；
- 坏文件样例：stderr 报错 + exit 2 + 无产物。

## 模块② 中文站点感知的失效检测（M3，核心亮点）

### 2.1 探测引擎（probe.py）
- 单次探测语义：每个 URL **一次逻辑探测**（HEAD；若 405/501 再降级 GET 限读前若干字节即断开——两者合计算一次，不算"二次探测"）；不携带 cookies/凭据；UA 为固定、明示身份的形态（见 ruleset `probe.user_agent`，M1 冻结）。
- 重定向：默认跟随至上限（`probe.redirect_max`），记录**跳转链**；超限 / 成环 → `review(redirect_loop/too_many_redirects)`。
- 超时 / 重试 / 降频：全部取自 ruleset 单点；串行执行，请求间隔 `probe.delay_s`。
- 记录（进 check.json）：`url`、`final_url`、`redirect_chain`、`http_status`（终态）、`error_class`（若网络层失败）、`verdict`、`reason`、`rule_id`（若规则命中）。

### 2.2 状态分类表 [冻结草案——M1 实测 + M3 定稿]

| 探测结果 | verdict | reason 码 | 说明 |
|---|---|---|---|
| 终态 2xx | `alive` | `http_2xx` | — |
| 终态 3xx（跟随耗尽仍 3xx） | `review` | `redirect_unresolved` | 罕见；保守 |
| 终态 404 / 410 | `dead` | `http_404` / `http_410` | **唯一**的通用判死证据 |
| 终态 401 / 403 / 405 / 406 / 429 / 451 | `review` | `http_4xx_blocked` | 权限/反爬/限流均可能；不判死 |
| 终态 5xx（含 521/522/523） | `review` | `http_5xx` / `cdn_blocked`（521 等） | 服务端问题可能恢复；不判死 |
| DNS 失败 / 连接超时 / 读取超时 / TLS 错误 | `review` | `dns_failure` / `connect_timeout` / `read_timeout` / `tls_error` | **网络不可达 ≠ 失效**（FR-12） |
| 规则命中（见 §2.3） | 按规则 | 规则 `reason` | 规则优先于通用映射 |

- **判定优先级**：规则命中 > 通用映射；多规则冲突时取**保守**（`review` > `dead` > `alive`）并在备注记录冲突（防"少判死"变"误判死"的反向）。
- 反爬降级规则示例形态（M1 用实测记录正式化）：知乎 403 → `review(rule: botguard)`；微博 302 → 跟随终态仍被风控 → `review`；B站 301/302 → 跟随跳转判定；掘金/CSDN 521 → `review(cdn_blocked)`。

### 2.3 降级规则库（ruleset.json 的 `degrade_rules` 节）[冻结草案]

```json
{
  "id": "R-ZHIHU-403",
  "match": {"host_suffix": "zhihu.com", "http_status": 403},
  "disposition": "review",
  "reason": "http_403_botguard",
  "note": "非浏览器请求返回 403；浏览器可正常打开（反爬，非失效）",
  "anchor": {"observation_id": "OBS-2026xxxx-zhihu-403", "check_status": "verified"}
}
```

- **锚点硬门**：`anchor.observation_id` 必须能在 `data/measurements/` 台账中解析到、且 `check_status=verified`；否则该规则**拒绝加载**，进"未启用清单"（原因显式列出）。"未启用清单"随每次运行的 stderr/报告输出——防"承诺可追溯、实际静默照判"。
- 规则字段语义：`host_suffix`（域名后缀匹配，精确到站点）/ `http_status`（观测状态）为**必填**；`match` 的扩展维度（路径前缀等）预留但 M3 不启用未实测维度。

### 2.4 失败语义（与退出码呼应）
- **文件级失败**（tree.json 不可读 / ruleset 解析失败 / 全量探测不可执行）→ exit 2，不产出 check.json；
- **单 URL 探测失败**（网络层错误）→ 该条落 `review` + 原因码，**不中断整批**；
- check.json 汇总块明示：总条数 / 各 verdict 计数 / 各 reason 计数（可对账）。

### 2.5 验收判据
- mock 场景逐项对照（403/302/521/404/超时/不可达/跳转成环）；
- 缺锚点规则 → 生效清单里无它 + "未启用清单"有它 + 原因可见；
- 同输入同 ruleset（含探测日期参数）→ check.json 逐字节一致（mock 环境下）。

## 模块③ 重复合并（M3）

### 3.1 URL 规范化（normalize.py，单点实现）[冻结草案]
固定顺序流水线（比较键用；原始 URL 永不改写）：
1. scheme 归一：`http` → `https`（比较键层面）；
2. host 归一：小写；去默认端口（:80/:443）；
3. 路径：去尾斜杠（根路径除外）；连续斜杠折叠；
4. 查询串：解析后**剥离追踪参数**（名单在 ruleset `tracked_query_params`：`utm_*`、`share_token`、`spm`、`scm`、`share_*`、`fbclid`、`gclid` 等）；剩余参数按键名排序后重序列化；
5. fragment：剥离；若两条 URL **仅 fragment 不同** → 仍合并，但组上附 `fragment_variant` 标记（报告提示"仅锚点不同"）；
6. 若 URL 有已实测短链映射（`shortlink_known`）→ 比较键用映射目标；若 check.json 有 `final_url` → 比较键优先用 `normalize(final_url)`。
- 未收录的短链**不猜**（题面边界纪律）：不参与合并，报告中可列为"疑似短链待人工确认"（P1）。

### 3.2 去重输出（dedupe.json）
- 重复组：`group_id`、成员（bookmark id + 原 URL）、**建议保留项**（策略：优先 https、优先无追踪参数、其次 `add_date` 最早、再次文件顺序最早——固定策略，可复现）；
- **绝不自动删除**：默认只出清单；`export --apply-dedupe` 为显式开关（用户确认动作）。
- 标题相似（`similarity.threshold`）→ 仅"相似提示组"分区呈现，不进入合并动作。

### 3.3 验收判据
- 规范化函数双向样例（每条规则：能合并 + 不该合并的对照样例）；
- 同输入 → dedupe.json 逐字节一致；真值合成集里"重复但形态不同"类全部命中。

## 模块④ 长期未访问画像与报告（M5）

### 4.1 长期未访问口径 [冻结草案]
- **基于添加时间的分档**（代理指标，报告显式注明口径）：`aging.tiers_days` = [365, 730, 1095] → 分档"1年+ / 2年+ / 3年+"；
- `add_date=null`（未知）的条目不参与分档，报告单列"添加时间未知：N 条"；
- 口径说明进报告（"以添加时间近似未访问；浏览器不导出真实访问记录"——诚实限制，与"未知不猜补"一致）。

### 4.2 报告结构（单文件 HTML，分节固定）
1. 摘要（各 verdict 计数 / 重复组数 / 未访问分档计数 / 未探测计数）
2. 失效清单（`dead`，逐条：标题 / URL / reason）
3. 待复核清单（`review`，逐条：标题 / URL / reason / 命中规则或原因码）
4. 重复清单（分组 + 建议保留项 + `fragment_variant` 标记）
5. 长期未访问画像（分档表 + 未知计数）
6. 建议清理清单（策略说明 + 待用户确认的条目；不自动执行）
7. **口径与免责**：三态定义、判定为辅助参考（以浏览器实际打开为准）、数据来源与生成参数（ruleset 版本哈希 / 探测日期）
- **资源零外链**硬断言：无 `<link>`/外链 `<script src>`/外链 `<img>`/`@import`/外部字体；CSS 内联；数据中的 URL 仅作为文本/链接展示（点击行为属功能，不算资源外链）。断网可开。

### 4.3 一键导回（export.py）
- 导出标准 Netscape Bookmark HTML（`<DT><H3>`/`<DT><A HREF ADD_DATE>` 结构 + `<!DOCTYPE NETSCAPE-Bookmark-file-1>` 头），保留文件夹层级与原始 URL；
- 默认**不删不改**（全量导回）；`--apply-dedupe` / `--exclude-dead` 为显式可选动作；
- 输出 HTML 转义纪律（标题/URL 中的 `<>&"` 正确转义；中文标题原样）。
- 验收：导出文件**往返解析一致**（机器）+ 浏览器实际导入（人工，M5 验收记录）。

### 4.4 验收判据
- 报告渲染层零判定逻辑（只消费 check.json/dedupe.json 的既有结论——单一渲染源的雏形）；
- 未探测项在报告中有独立分区/计数（不得混入存活）；
- 断网打开报告渲染正常；导出往返一致。

## 模块⑤ 真值基准（M1 数据先行 + M4 基准）

### 5.1 合成书签集（M1，tools/gen_fixtures.py）
- 布局草案：`data/fixtures/<set-id>/`（`bookmarks.chrome.html`、`bookmarks.chrome.json` 双格式 + `truth.json` + `manifest.json`）；
- 生成器纪律（plan/03 §7）+ `--check` 位级一致守门；
- URL 全部使用保留域名（`*.invalid` / `example.invalid`），**零真实站点 URL**；反爬场景由 mock 站点模拟（`*.mock.invalid` 主机在基准运行时重写为 loopback 地址）；
- `truth.json` 只存**输入与期望**（哪些应 `dead` / 哪些应合并到哪个组 / 哪些应 `review` 及原因类），**不存 observed 类字段**（"观测"必须由基准运行时实算）；
- `manifest.json`：覆盖声明（三类易错形态的**件数与清单**——总数/采样数双登记，"抽样覆盖非穷举"显式声明）、生成参数（seed）、文件 sha256 表。

### 5.2 基准 runner（M4，tools/bench.py）
- 两条独立层：
  - **样本驱动**：合成集 → 真喂引擎（解析/规范化/分类）→ 与 `truth.json` 对账；
  - **规则驱动**：不读真值库，直接遍历 ruleset 每条规则与通用映射表全组合喂分类器，断言"该命中/不该命中"（含**反向样例**：不该命中的站点/状态组合不得命中）。
- 指标（写进 README 表 + manifest 门槛，**门槛是数据非代码**）：
  - 致命误报 `false_dead`（真值为 alive/review 却被判 dead）= **0（硬门）**；
  - 三类易错形态命中率（review 类不得被计入 dead；dead 类不得漏进 alive）分别统计；
  - 重复合并类：真值重复组全部合并且无误合并。
- **可证伪探活**：注入缺陷（如把 403 通用映射改成 dead）→ 基准必须报未达标（exit 1）——作为常驻测试。
- 退出码三语义（0/1/2）锁进测试；`--only <suite>` 支持部分运行，未知名 → exit 2；空分母分支 = `not_enabled` + exit 1（不冒充通过）。
- 全程离线（仅 loopback mock）；断网可复跑。

### 5.3 基准与数据台账的联动
- 每次里程碑收尾复跑双基线（bench + 全量测试）防回退；
- 规则包/合成集改动 → 生成器整目录重生成 + `--check` + manifest sha256 三联动更新。

## 附：CLI 规格草案（M2–M5 逐步实现，M5 冻结）

| 子命令 | 用途 | 关键参数 | 里程碑 |
|---|---|---|---|
| `import <files...>` | 解析 + 合并 → tree.json | `--out`（默认 stdout 摘要 + `tree.json`） | M2 |
| `check <tree.json>` | 探测 + 分类 → check.json | `--rules`（默认 data/rules/ruleset.json）、`--probe-date`、`--out` | M3 |
| `dedupe <tree.json>` | 规范化去重 → dedupe.json | `--check check.json`（可选，用 final_url）、`--out` | M3 |
| `report` | 单文件 HTML 报告 | 输入 tree/check/dedupe、`--out report.html` | M5 |
| `export` | 导回 Netscape HTML | `--apply-dedupe` / `--exclude-dead`、`--out` | M5 |
| `run <files...>` | 全链路编排（一条命令出结果） | `--out-dir` | M5 |

- 全部子命令：`--help`、退出码契约（plan/03 §8）、编码守卫、输出确定性（除显式日期参数）。
- **用户 CLI 只留用户要用的命令**；发布/维护类工具一律 `tools/`（不进用户命令面）。
