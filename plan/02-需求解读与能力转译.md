| 编号 | 需求 | 说明 |

## 4. 边界与非目标（承接 01 §6，工程侧落点）

- **不做批量爬取 / 不登录 / 不做内容抓取 / 遵守降频**：探测层只发单次 HEAD/GET（必要时降级），不带凭据、不落盘响应体（仅记录状态与必要头部特征）。
- **零上传**：无任何远端写入代码路径；报告与导出文件纯本地生成。
- **非目标**：云同步、服务端常驻、收藏内容存档、浏览器扩展——均不做（01 §6.3）。
- **结论纪律**：`review`（待复核）与 `dead`（失效）不得混用；网络不可达、403/521 反爬拦截一律 `review`；"未探测"不得呈现为已判定（报告显式分区）。
- **品牌隔离**：本项目文档不提及任何姊妹项目，独立署名与独立定位（01 §6.5）。

## 5. 判定语义总口径（"不虚高"纪律的领域形态）

- 三态定义（机器值 → 报告标签）：
  - `alive` → 存活：探测终态为 2xx，或降级规则明确判存活；
  - `dead` → 失效：**仅限**终态 404/410 等确定性证据（或规则明确判失效，且该规则挂实测锚点）；
  - `review` → 待复核：网络不可达 / 超时 / 403 / 401 / 429 / 5xx / 521 等**一切"无法确证失效"**的情形。
- **绝不把"没确证"判成 `dead`；绝不把"未探测"写成 `alive`**——与合规审计类工具"不得把'没做'记成'不用做'"同源，本项目的镜像纪律是"不得把'可能还活着'记成'死了'"（误报失效是本项目最贵的失真）。
- 全链路零 LLM（决策记录 D14）：所有判定由确定性解析 + 规则产生，可复现、可离线复跑。
