## 3. 发布计划（M6 执行清单，届时逐项留档）

> 总顺序：**脱敏与干净环境证据先行 → 先 private 建仓 → CI 首跑绿 → tag + Release → 复核 → 切 public → 发布后全新 clone 复核**。

### 3.1 发布前（发布物与证据）
- [ ] 全量回归：双解释器测试全绿 + 基准达标 + 生成器 `--check` 位级一致（`git status` 零变化）
- [ ] 干净环境验证：新目录 clone（或 `git archive` 导出树）+ 全新 venv，**按 README 逐条执行**并记录每条退出码（对照明示语义）；暴露问题修复 + 回归测试
- [ ] 发布物：按 M5 实况定案产物（sdist/wheel/便携 zip）；构建产物留底仓库树外；zip 用固定时间戳（`ZIP_STORED` + 固定 `date_time`，两次打包逐字节一致）→ sha256 留档
- [ ] 产物与发布源码同基线（`git diff <构建提交>..HEAD -- src/ tools/` 为空，否则重建）
- [ ] README 终检：状态行转正（🚧→✅ vX.Y.Z + Release 链接）+「下载即用」+「已知环境问题」+ 计数全仓一致（当轮实测）

### 3.2 脱敏四步（命令 + 结论逐项留档 RELEASE-M6）
- [ ] ① 文件名扫描：`git ls-files` 无 `.env/.key/secret/token` 类；`.gitignore` 覆盖运行产物与个人材料
- [ ] ② 内容级扫描（全部跟踪文本）：密钥形态 / 手机号 / 身份证 / 本机个人路径 / 内网 IP / 邮箱（**扫描 token 运行时实算，源码与留档零词面**；个人路径以组合签名匹配，防裸词误报）
- [ ] ③ 二进制样例扫描（如适用）：zip 类产物逐条目扫；含真实个人信息者移出仓库
- [ ] ④ 历史扫描（若已推送则先改写；**未建远端 = 零成本窗口，一次做完**）：历史三扫 0 命中 + 提交元数据邮箱决策执行
- [ ] 发布物本体扫描：全 dist 树强标记扫描（Python 字节读法）；zip 通路与目录通路都跑
- [ ] ⚠️ 已知任务：当前仓库提交元数据含**真实个人邮箱**（本地 git 全局配置所致）→ 发布前决策：改写为 GitHub noreply（`<id>+<user>@users.noreply.github.com`），未建远端期间执行零成本；改写后验证 `git log --format='%ae %ce'` 两字段

### 3.3 建仓与 CI
- [ ] `gh repo create`（**先 private**）→ 固化 remote → push main
- [ ] CI 首跑：**预算多轮诊断**（首跑暴露的类型多为：编码/代码页、EOL、extras 缺测试期依赖、旧解释器可用性）；失败面签名逐条定位；修复提交如实配对留档
- [ ] 对账：`gh api .../actions/runs` 的 head_sha 与本地 `git log` 逐提交配对（push 事件数 = run 数，快照 + 可复跑规则写法）
- [ ] tag push 是否触发 run 以实况记录（两种行为都出现过）

### 3.4 tag 与 Release
- [ ] 对外动作集中确认（一次 AskUserQuestion）：tag 版本号 / Release 说明 / topics / 可见性切换
- [ ] annotated tag 打在含终态回写的提交上；`gh release create --notes-file`（附件 **ASCII 名**）
- [ ] 发布物本体复核：`gh release download` 真下载 → sha256 与留档逐位一致 → 中立目录解压 → 冻结态自检（如为 zip）
- [ ] 切 public：三清后切换（历史三扫 0 / 坏 blob 修净 / 失败 run 已删）；切换后复核 `gh repo view --json visibility`

### 3.5 发布后复核
- [ ] GitHub 全新 clone → 历史扫描 + 全量测试 + 端到端演示复跑
- [ ] `plan/RELEASE-M6.md` 发布后回填（run id / Release URL / 复核结论）→ 小提交推送等 CI 复绿（不迁 tag）
- [ ] 收尾：README 状态终检、缓议项清零（含"显式跳过"决策）、HANDOFF 完结快照

## 4. 风险与预算

| 风险 | 概率/影响 | 处置 |
|---|---|---|
| CI 首跑暴露环境差异（编码 / 旧解释器可用性 / EOL） | 高 / 中 | 开发期前置工程（K8 编码守卫、eol=lf、`fetch-depth:0`、dev extras 覆盖测试期依赖、3.8 兼容写法）+ 发布期预算多轮诊断；失败面签名定位 |
| ubuntu 新镜像对 Python 3.8 支持存疑 | 中 / 低 | 矩阵已裁剪（旧解释器只在 windows 守）；首推实测后按实况补记，不硬凑 |
| 实测站点反爬形态随时间漂移 | 中 / 中 | 规则全部挂观测日期 + 查证状态；重测流程化（复跑命令在台账）；旧观测不删只标注 |
| 真实站点探测不可达（本机网络环境） | 中 / 低 | 实测记录如实标注渠道与失败原因（"待复核"）；基准全离线不依赖真站点 |
| 发布物含个人路径/邮箱等（脱敏） | 低 / 高 | 未建远端窗口一次做完：扫描器 + 邮箱改写 + 留档措辞占位化（历史教训：留档自命中是必踩而非可能踩） |
| 大文件 / 依赖镜像不可用 | 低 / 低 | 零运行时依赖；pip 走镜像 + NO_PROXY 纪律（本机已验证） |
