## 2. 实测记录规范（D-3，M1 细化）

每条观测（observation）字段：

```json
{
  "id": "OBS-20261015-zhihu-403",
  "site": "知乎",
  "url": "https://<实测样例 URL>",
  "http_status": 403,
  "final_url": null,
  "redirect_chain": [],
  "error_class": null,
  "tool": "curl 8.x / 探测脚本 + 说明",
  "observed_date": "2026-10-15",
  "check_status": "verified",
  "notes": "非浏览器请求 bot 拦截；浏览器可正常打开"
}
```

- `check_status`：`verified`（已复核，可支撑规则生效）/ `pending`（待复核，锚点指向 pending → 规则不生效、进"未启用清单"）。
- 探测合规：单次探测 / 不登录 / 不抓内容 / 遵守降频（data/README §1.3）；实测样例 URL 从题面锚点与公开站点首页/文章页选取，**只探测状态，不落正文**。
- 人读台账：`data/measurements/observations.md`（表格 + 复跑命令）；机读：`observations.json`（规则锚点解析源）。两者 sha256 登记进台账。

## 3. 生成器与冻结纪律（通用）

1. 所有生成器（`tools/gen_ruleset.py`、`tools/gen_fixtures.py`）：自研 splitmix64 确定性 RNG、固定 seed、**无系统时钟**；输出经显式 sort；写盘 `write_bytes`/`newline="\n"`。
2. `--check` 模式：重新生成到内存 → 与仓库现有文件**逐字节比对**（不一致即 exit 1 + 差异清单）；CI 与每次收尾必跑。
3. 冻结产物的字节保护：`.gitattributes` 中 `data/** -text`（防 EOL 归一化改写字节）。
4. 改数据 = 改生成器输入 → **整目录重生成** → `--check` 通过 → manifest sha256 / 台账 / 基准三联动更新，同一提交落盘。
5. **真值库只存"输入与期望"**：`truth.json` 出现 `observed` 类字段即红（观测必须由基准运行时实算）。

## 4. 基准计划（M4）[已落地 2026-10-15（M4）：tools/bench.py + tests/test_bench.py；实测指标见 README"内置基准"节]

### 4.1 评测对象与口径
- 评测对象 = 检测引擎（分类 + 规则加载）与去重引擎的**行为输出**，真喂引擎后与真值对账（不是"比对两份预计算答案"）。
- M4 落地口径：mock 重写按 manifest `mock_host_scenarios` 场景驱动（HTTP 场景 = 完整原路径前插主机命名空间段 + 尾插 `status/<场景码>`——保住主机与页内区分度，去重键不塌缩；hang → 挂起路径；unreachable → 运行时找空端口并断言确实拒绝连接）；scheme 同步 http 化（mock 无 TLS）；重写后唯一 URL 只探一次结果扇回（跨来源重复收藏语义不变、耗时减半）。

### 4.2 套件与指标

| 套件 | 驱动方式 | 主要指标 | 门槛（manifest 下发） |
|---|---|---|---|
| B1 分类·反爬类 | 样本驱动（合成集 mock 场景） | 403/521/302 类应落 `review` 的命中率；**误判 `dead` 数** | false_dead = 0（硬门）；命中率 ≥ 门槛值 |
| B2 分类·不可达类 | 样本驱动 | DNS 失败/超时应落 `review` 的命中率；误判 `dead` 数 | false_dead = 0（硬门） |
| B3 分类·死链类 | 样本驱动 | 404/410 应落 `dead` 的命中率；漏判（落 alive/review）计数 | 命中率 ≥ 门槛值 |
| B4 分类·规则驱动 | **规则驱动**（不读真值库，遍历规则表 + 通用映射全组合） | 每条规则"该命中/不该命中"断言（含反向样例） | 100% 断言通过 |
| B5 去重类 | 样本驱动 | 真值重复组合并率；误合并数 | 合并率 ≥ 门槛值；误合并 = 0（硬门） |
| B6 一致性 | 样本驱动 | 同输入两次运行 check.json 逐字节一致 | 位级一致 |

- **反向样例必配**：每条降级规则配"不该命中它"的对照（不同站点 / 不同状态），防"适用域写宽了基准永远绿"。
- **覆盖声明双数登记**：manifest 逐形态记"应有件数 / 实际覆盖件数 / 清单"，并显式声明"抽样覆盖非穷举"。
- **门槛是数据非代码**：读取自 manifest；缺失 → exit 2；不在引擎/基准里内联默认值。

### 4.3 mock 站点（tools/mock_site.py）
- 本地 `http.server`（仅 loopback），按路径脚本化响应：`403 / 302(含风控终态) / 301 / 521 / 404 / 410 / 200 / 超时(自定义 handler 挂起) / 连接拒绝(不监听端口)`；
- 合成集 URL 用 `*.mock.invalid` 主机名，基准运行时**重写为 `127.0.0.1:<port>`**（端口运行时分配，不进 fixtures 字节）；重写映射进基准输出（可核对）；
- 基准前断言"待探测 URL 集（重写后）全部为 loopback"，任一真实外网 URL 出现 → 基准 exit 2（防"基准偷跑外网"）。

### 4.4 探活（可证伪）与退出码 [已落地：探活 = --inject-defect 403-dead 端到端测试 + 变异验证（classify 通用映射 403→dead → bench --only B1 exit 1，还原绿）]
- 每个套件配注入缺陷的探活测试（例：把 403→dead 打进分类器 → B1 必须报未达标；把重复组真值改成"不应合并" → B5 必须红）；探活打**端到端入口**（`bench.py` 真返回非 0），不止函数层；
- 退出码三语义：0 达标 / 1 未达标（含空分母 `not_enabled` 分支）/ 2 用法与未知名；全部锁进测试。

### 4.5 指标写进 README [已落地：README"内置基准"节，2026-10-15 实测——B1 3/3、B2 8/8、B3 3/3、B4 372/372、B5 4/4 误合并 0、B6 位级一致；false_dead=0]
- 达标后的指标表（各套件命中率 / false_dead / 位数）写进 README"评测"节——这是项目可信度的核心证据；未达标的数字如实写或暂缺（不预填）。
