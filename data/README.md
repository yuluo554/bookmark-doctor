## 2. 数据源可获取性记录

- **可获取（✅）**：
  - 本地书签文件解析——纯文件、无网络依赖，Netscape Bookmark HTML 与 Chrome/Edge `Bookmarks` JSON 均为公开格式，解析简单。
  - 微信公众号文章 `mp.weixin.qq.com/s/...`——实测连发 5 次均 200，正文 `js_content` 完整；正文图 `mmbiz.qpic.cn` → 200 image/jpeg。
  - GitHub / 通用站——curl 200，作为基线对照。
- **阻断（⬜，反爬原因逐条）**：
  - 知乎 `zhihu.com` → **403**（bot 拦截）。
  - 微博 → **302**（需跟随跳转 + 风控）。
  - B站 → **301/302**（需降级判定）。
  - 掘金 / CSDN 真链接 → **521**（反爬 CDN 拦截）。
  - **阻断性质说明**：以上均为**平台反爬拦截**，**非"不可获取"**——链接在浏览器中可正常打开。因此本项目**不将这些状态判为失效**，而是作为降级规则库的输入，判"待复核"。
- **软论据（⬜）**：GitHub 检索式空白结论，见 §1.1；复跑检索式即可核验。

## 3. 合成数据纪律

本项目全部测试书签集为**合成数据**，必须遵守：

1. **假域名白名单**：合成书签 URL 一律使用保留示例域名（如 `example.invalid` 类，或 `*.test.invalid` 命名空间），**不得使用任何真实站点 URL**（尤其不得使用真实的中文站点 URL 做合成样本）。
2. **不植入真实个人信息**：不得从任何真实书签导出文件中复制内容进入样例集。
3. **植入真值显式登记**：每个合成书签集的元数据必须登记植入真值——**哪些书签应判失效 / 哪些应判重复（合并到哪一项）/ 哪些 403 或 521 应标"待复核"而非失效 / 哪些因网络不可达应标"待复核"**。真值由**程序化标注**生成（生成器同时输出书签文件与真值 JSON），禁手工标注以免漂移。
4. **双格式覆盖**：合成集须同时提供 Netscape Bookmark HTML 与 Chrome/Edge `Bookmarks` JSON 两种格式，并保证往返解析一致。
5. **覆盖易错形态（三类强制）**：合成集必须显式覆盖——①"403/521 反爬被误判失效"（应判待复核）；②"网络不可达被误判失效"（应判待复核）；③"重复但 URL 形态不同"（应合并）。各形态最低覆盖项写进基准 manifest，题面不写硬数字。
6. **反爬状态模拟不依赖真实站点**：合成集的 403/302/521 场景通过**本地 mock 响应**模拟，基准复跑**不出网**，保证离线可复现。

## 4. 数值口径纪律

- **数值口径一处定义、多处引用**：探测超时秒数、重试次数、降频间隔、URL 规范化规则表、长期未访问分档阈值——**只在降级规则库 / 配置单点定义**，引擎、报告、基准、文档全部引用，**禁止在注记里手写第二份口径表述**。
- **降级规则库每条规则须携带**：站点标识、观测状态、判定处置（失效 / 待复核 / 存活）、实测记录锚点（观测日期 + 三态）；**缺锚点的规则不得被引擎加载生效**。
- **题面与文档引用**仅限 §1.2 已实测清单，不得凭印象新增站点状态。
- **不写漂移硬数字**：书签数、基准用例数、命中率具体值不写入题面，只写指标口径与覆盖度要求（以末态回填）。
